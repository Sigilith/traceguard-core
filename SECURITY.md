# Security Policy

## Supported versions

Security fixes are prioritised for the latest version on the `main` branch and the latest published release. Older versions may not receive fixes.

## Reporting a vulnerability

Please do not publish exploit details, credentials, personal data, or proof-of-concept material in a public issue or pull request.

If GitHub's private vulnerability reporting is enabled for this repository, use **Security → Report a vulnerability** to submit a private report. If that option is unavailable, contact the repository maintainer privately through the verified contact method on the Sigilith GitHub profile and request a secure reporting route. Do not include live credentials in an initial message.

Please include, where safe:
- A concise description and affected version or commit.
- Reproduction steps using synthetic data.
- Expected and observed behaviour.
- Potential impact and any practical mitigations.

Please allow reasonable time for triage and remediation before public disclosure. No response-time guarantee or bug-bounty programme is implied by this policy.

## Scope and limitations

This repository is a software project, not a security certification. A report or fix does not establish that the wider ThreeLineage system or any deployment is secure. Do not access, modify, or disrupt systems or data that you do not own or have explicit permission to test.
